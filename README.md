# 划线笔记 / Underline Notes

在 Chrome 中给网页划线、写批注，把摘录保存到本地文件夹，或写入 flomo、思源笔记。默认使用本地文件夹，每条摘录都是可以用文本编辑器打开的 Markdown 文件；想按卡片回顾时，再用 Obsidian 打开同一个文件夹，启用配套插件即可。选择 flomo 则可在不同设备上回顾，无需配置本地文件夹或安装 Obsidian。思源用户可安装配套卡片盒插件，浏览摘录、随手记和每日回顾。

浏览器扩展和 Obsidian 插件均支持可选的自动标签，只能从已有标签中选择，不允许模型创建未知标签。配置模型并开启该功能后，保存笔记时会把当前卡片的部分内容发送到所选模型服务。

## 本地安装

桌面版 Chrome 120+ 可直接安装发布包。Obsidian 和思源用户可下载对应的卡片盒插件，无需构建源码。

| 下载 | 用途 |
| --- | --- |
| [Chrome 扩展 ZIP](https://github.com/rockbotcc/underline-notes/releases/latest/download/underline-notes-chrome.zip) | 网页划线、批注，保存到本地文件夹或写入 flomo、思源 |
| [思源插件 ZIP](https://github.com/rockbotcc/underline-notes/releases/latest/download/underline-notes-siyuan.zip) | 思源 3.8.10+ 卡片流、随手记、每日回顾；[安装说明](#思源插件安装与使用) |
| [Obsidian 插件 ZIP](https://github.com/rockbotcc/underline-notes/releases/latest/download/underline-notes-obsidian.zip) | 在 Obsidian 1.6+ 中按卡片浏览已有摘录 |

**让Codex、WorkBuddy等Agent帮你安装。** 按希望的保存位置，任选一句发给 Agent：

保存到本地文件夹（以后也可用 Obsidian 回顾）：

> 请按 https://github.com/rockbotcc/underline-notes/blob/main/INSTALL.md 用发布包帮我安装 Chrome 划线笔记，把摘录保存到文稿里的「划线笔记」文件夹。

写入 flomo：

> 请按 https://github.com/rockbotcc/underline-notes/blob/main/INSTALL.md 用发布包帮我安装 Chrome 划线笔记，把摘录写入 flomo，并引导我在扩展设置中填写 flomo API URL。

写入思源笔记并使用卡片盒：

> 请按 https://github.com/rockbotcc/underline-notes/blob/main/INSTALL.md 用发布包帮我安装 Chrome 划线笔记和思源卡片盒插件，把摘录写入思源笔记，并引导我在扩展设置中配置思源地址、API Token 和目标笔记本。

选择本地文件夹时，确认摘录已保存后，Agent 会问你是否要用 Obsidian 回顾。你可以选择安装 Obsidian 和配套插件、只给已有的 Obsidian 安装插件，或只用 Chrome。如果 Chrome 已装好，只需说「继续为刚才的笔记文件夹安装 Obsidian 插件，并打开卡片盒」。选择 flomo 时，在 flomo 中确认收到测试笔记即可完成安装；需要账号具备相应 API 权限，详见[写入 flomo](#写入-flomo)。

**手动安装**

1. **安装 Chrome 扩展。** 下载上方 Chrome ZIP，将它解压到长期保留的文件夹，例如「应用工具/划线笔记扩展」。在地址栏打开 `chrome://extensions`，开启「开发者模式」，点击「加载已解压的扩展程序」，选择解压后能直接看到 `manifest.json` 的文件夹。将扩展固定到工具栏，并保留这个文件夹。
2. **选择笔记写入位置。** 打开扩展「选项」。保存到本地时，保留默认的「本地 Obsidian」，点击「选择笔记文件夹」，新建「划线笔记」或选择已有文件夹并允许读写；在网页上划线并保存批注，点击「立即同步笔记」，在所选目录的 `Reading/Cards/` 中核对 Markdown 文件。写入 flomo 时，选择「flomo」，填写自己的 API URL 并点击「保存写入设置」；随后新建一条笔记，在 flomo 中核对内容，具体见[写入 flomo](#写入-flomo)。完成任一方式的验证后即可日常使用。
3. **本地保存可选：用 Obsidian 看卡片。** 下载上方 Obsidian ZIP 并解压。在 Obsidian 中选择「打开本地仓库」（Open folder as vault），打开第 2 步选的笔记文件夹。进入「设置 → 第三方插件」，打开插件文件夹，把解压得到的 `noting` 文件夹放进去（最终位置为 `.obsidian/plugins/noting/main.js`）。退出仓库的限制模式（如已开启），刷新已安装插件列表，启用「划线笔记 / Underline Notes」，再打开 `Reading/卡片盒.md`。

升级已有安装或使用自定义 Obsidian 配置目录时，请参见[本地安装指南](INSTALL.md)。

## 源码与发布

正式版本通过 GitHub Actions 发布：同步更新 npm、Chrome、Obsidian、思源的版本号及 `versions.json`，添加 `releases/<版本>.md`，再推送与版本号一致的 Git 标签（不加 `v`）。工作流会执行类型检查、单元测试、flomo 与思源扩展浏览器测试，生成 Chrome、Obsidian、思源三个安装 ZIP、Obsidian 更新文件及 SHA-256 校验文件，并创建 Release。本地可先运行 `npm run build` 和 `node scripts/package-release.mjs` 检查 `dist-release/` 中的产物。

- `browser/` 包含 Chrome 扩展的清单、设置页和源码。`obsidian/` 包含社区插件的源码与样式。`siyuan/` 包含思源卡片盒插件。各端共用的笔记模型、Markdown 格式和同步函数在 `shared/`。
- 运行 `npm run check && npm test && npm run build` 验证所有端的源码。测试需要支持 TypeScript 类型剥离的 Node.js，例如 Node.js 22.18 及以上版本。
- Chrome Web Store 使用 `browser/manifest.json` 中的版本号。运行 `npm run build` 和 `node scripts/package-release.mjs`，上传生成的 `dist-release/underline-notes-chrome.zip`；包内包含 `LICENSE`、`NOTICE` 和第三方依赖的 `THIRD_PARTY_LICENSES.txt`。商店文案、截图和审核说明见 [Chrome 发布材料](store/chrome/listing.md)，扩展的数据处理说明见[隐私政策](PRIVACY.md)。
- Obsidian 社区目录读取仓库根目录的 `manifest.json`。发布时同步维护 `versions.json` 的最低兼容版本，在 GitHub 创建与插件版本完全相同的 Release 标签（如 `0.4.0`），并分别上传 `dist-release/` 下的 `main.js`、`manifest.json`、`styles.css`、`LICENSE` 和 `NOTICE`。Obsidian ZIP 也包含许可证与署名文件；独立更新使用的 `main.js` 内嵌完整许可证和 NOTICE。首次上架还需向 [Obsidian 社区目录](https://github.com/obsidianmd/obsidian-releases) 提交插件信息。

## Obsidian 卡片盒体验

- **记录与回顾**：卡片按时间、标签、内容、来源排列，优先展示自己的批注和补写想法；摘录以细线区分，仅有摘录时按正文展示。右上角「…」菜单可编辑或打开笔记，Command/Ctrl + Enter 保存；浏览器连接同一仓库后双向同步。
- **按来源**：侧栏「按来源」将同一篇文章的记录自动归组，展示记录数、内容摘要和已有 Markdown 图片引用的缩略图。点击来源标题或「查看全部记录」集中回顾、补写，并打开原文或本地全文。来源按最近更新排序，详情按记录时间排列；搜索命中一条笔记时仍展示该来源的全部记录。无来源的随手记单独归组。
- **随手记**：顶部输入框可新建独立想法，不必填写标题。文件保存在 `Reading/Cards/Local/`。
- **搜索与标签**：搜索摘录、批注、补写与文章标题；想法中的 `#标签`、`#领域/写作` 会进入侧栏。标签按领域折叠，点击父标签可查看所有子主题的卡片，数量按卡片去重。待消化筛选显示还没有写下自己想法的摘录。
- **每日回顾**：每天从当前搜索范围稳定选取最多 8 张卡，逐张阅读、补写。首版不保存完成进度，不含提醒推送或间隔记忆算法。
- **阅读足迹**：查看已保存文章；点击「接着读」在侧栏打开本地正文。卡片底部的来源标题进入同源记录详情，详情中的「本地全文」可继续阅读。
- **自动标签**：保存笔记后从已有的项目、领域、收件箱或资源标签中选择，不创建未知标签，保留手写标签。标签显示在卡片时间下方和侧栏，点击即可筛选。

## 配置自动标签

浏览器扩展：先在 Obsidian 中安装并启用划线笔记插件。插件从整个仓库的 Markdown 元数据缓存读取正文 `#标签` 和 YAML `tags`，自动导出到资料文件夹下的 `Data/vault-tags.json`（默认 `Reading/Data/vault-tags.json`）。也可在插件设置点击「导出全仓库标签」。浏览器选择对应的 Obsidian 仓库文件夹后，只从该文件读取候选，不使用浏览器本地笔记或 flomo 标签。Obsidian 关闭时使用最后一次导出的列表；标签文件缺失、无权限或损坏时提示并跳过打标，空列表不调用模型。

在扩展设置的「大模型自动标签」中填写兼容 Chat Completions 的接口地址（如 `https://your-provider.example/v1`）、API Key 和模型名称，开启「自动添加已有标签」并保存。默认关闭；开启后保存划线或笔记时最多添加三个已有标签，直接追加到批注并随笔记同步到本地或 flomo。写入 flomo 时也可以连接 Obsidian 文件夹读取标签。模型返回的未知标签会被代码过滤，失败或超时仍保存原笔记，设置页显示错误。API Key 仅存本机，不进入备份或网页；发送范围见[隐私政策](PRIVACY.md)。

以下为 Obsidian 插件的独立配置：

在「设置 → 划线笔记 / Underline Notes → AI 自动标签」填写兼容 Chat Completions 的接口地址、API Key 和标签模型 ID。已有的模型配置会继续使用，不再需要向量模型。配置完成后，“保存后自动添加标签”默认开启，可在设置中关闭；“测试连接”只发送测试短句。

在卡片盒新建、编辑保存，以及浏览器同步或外部编辑产生卡片修改时触发。插件需在 Obsidian 中运行。打开仓库不会批量处理旧卡片；内容未变且已处理过时不重复请求。模型最多收到当前卡片的 200 字标题、1800 字批注、1800 字延伸思考、1200 字摘录、最多 30 个手写标签，以及整个仓库的已有标签名称。不发送上下文、全文、其他卡片正文、附件或历史讨论。普通标签、多级标签和 YAML tags 都可作为候选，不限定 P.A.I.R. 分类，也不截取前 80 或 200 个标签。

AI 从整个仓库的已有标签中选择最多三个，并跳过重复的手写标签；未知标签会被代码过滤。Obsidian 自动标签单独写在卡片尾部的 `noting:tags` 区域中，不改写批注或浏览器维护的元数据；浏览器重新同步会保留这一区域。标签可在卡片和侧栏中筛选，也可由 Obsidian 原生标签索引读取。

已有卡片可在设置中点击“整理旧卡片标签”：按队列逐张调用模型，补齐未打标卡片，并重新归类已有自动标签。该操作保留手写标签和正文，可能产生模型费用；关闭自动标签可停止剩余队列并丢弃进行中的结果。旧的单级或多级标签仍可读取、显示和筛选，不会在打开仓库时自动改写。

快速连续保存时按最新内容处理；请求期间内容变化会丢弃旧结果。模型失败、格式错误或请求超时不影响保存笔记，卡片会提示，下次保存时重试。关闭自动标签或切换配置后，进行中的旧请求不会再写入。

“和 AI 讨论”“发现关联”功能暂时移除。已有讨论历史、关联配置及已写入的笔记内容保留。API Key 仍保存在插件的 `data.json` 中，未加密，不应公开分享该文件。

## 开始使用

1. 在普通网页中选中文字，点击浮动工具条的颜色进行划线，或点击「记笔记」同时保存批注。
   将鼠标移到网页图片上（至少 48 × 48 像素），点击「收录图片」直接收录，或点击「记笔记」预览图片、写下批注再保存。图片记录可在本页侧栏继续编辑、定位原图或删除，连接笔记文件夹后会生成带图片的独立卡片，并出现在「按来源」的缩略图中。
2. 点击已有高亮查看批注；双击笔记内容或点击右上角铅笔进入编辑，可修改颜色或删除。点击 Chrome 工具栏的「划线笔记 / Underline Notes」图标打开本页侧栏，文章笔记和批注默认以文本完整展开，双击内容或点击铅笔即可添加、修改笔记。
3. 在侧栏打开「设置与文件写入」，选择笔记写入位置。本地保存需要选择文件夹，扩展会创建 `Reading` 子文件夹；写入 flomo 则按[写入 flomo](#写入-flomo)配置 API URL，配置后新增或修改的笔记才会发送，已有笔记不会批量补发。
4. 本地保存且使用 Obsidian 时，检查仓库名称与 Obsidian 显示的名称一致。在 Obsidian 中打开 `Reading/卡片盒.md`，以阅读视图直接浏览展开的卡片。每张卡片也能单独打开、链接和补写。选择 flomo 时，直接在 flomo 中回顾已写入的笔记。

工具条与侧栏交互参考 Web Highlights。支持跨文本节点和段落的划线。弹窗中的笔记可用 Command/Ctrl + Enter 保存。

收录 HTTP / HTTPS 图片时，扩展会下载图片并保存在浏览器本地，JSON 备份也包含图片。连接笔记文件夹后，图片文件写入所选目录的 Attachments 文件夹，卡片通过相对路径引用。单张图片上限为 12 MB。旧记录在再次保存时下载原图。

点击笔记弹窗或侧栏外的网页区域即可关闭。划线笔记有未保存修改时会先确认是否放弃；侧栏中的文章笔记草稿会保留，重新打开后可继续编辑。

笔记阅读状态保留全文和换行，长内容随页面展开；保存后回到阅读状态。编辑划线笔记时不显示引用正文，复述与 Markdown 提示放在输入框占位符中。文章笔记编辑区与 Obsidian 卡片输入区仍保留独立提示，记录方式由你选择。文章笔记支持取消修改及 Command/Ctrl + Enter 保存。

## 写入 flomo

在浏览器扩展「设置与文件写入」的「笔记写入位置」中选择 **flomo**，粘贴你的 **flomo API URL**，点击「保存写入设置」。API URL 从 [flomo 的 API 设置](https://flomoapp.com/mine?source=incoming_webhook)获取，账号需具备[相应 API 会员权限](https://help.flomoapp.com/advance/api.html)。使用 flomo 无需选择本地文件夹或安装 Obsidian 插件；已有用户升级后仍默认使用本地输出。

启用后新增或修改的每条划线、批注和文章笔记会作为独立记录写入 flomo，按「自己的笔记 → 引用摘录 → 文章标题及 `#划线笔记/域名` 二级标签（如 `#划线笔记/example.com`，域名取自来源 URL，不含路径、参数和端口） → 来源 URL」排列，以单换行紧凑展示。批注直接放在开头，引用用引号区分，不添加“我的批注”“摘录”“来源”等说明标签；没有批注时直接展示引用。图片以原图链接和说明写入；全文、图片文件和自动阅读日志保留在浏览器，不上传 flomo。内容连同来源超过 5000 字时会提示缩短，原始笔记仍完整保存在本机。

这是单向追加：修改已发送的笔记会新增一条记录；相同内容重复保存、定时同步不会重复写入。清空文章笔记或删除浏览器记录会取消相应待写入项，已经写入 flomo 的记录需在 flomo 自行修改或删除。flomo 中的修改不会回传浏览器。

写入失败会保留队列，浏览器运行时通常每分钟重试，也可点击「立即同步笔记」。网络超时可能发生“flomo 已保存但浏览器未收到确认”，此时重试仍可能产生重复记录。设置页和网页侧栏会显示当前状态。

切换位置会暂停原位置的输出，已有笔记和导入的备份不会批量补发到 flomo。切回本地 Obsidian 后，原有本地文件队列继续同步。每台设备需分别安装和配置浏览器扩展；网页划线定位、浏览器备份和本地 Obsidian 文件不会通过此功能跨设备同步。API URL 只保存在本机扩展数据库中，不发送给网页，也不包含在 JSON 资料备份中。

## 写入思源笔记

选择扩展设置中的 **思源笔记**，填写服务地址和 API Token，点击「测试连接并读取笔记本」，选择已打开的笔记本并保存。默认地址为 `http://127.0.0.1:6806`，Token 在思源「设置 → 认证」（部分版本在「关于」）中获取。首版需要结构化文档 API，以思源 3.8.10 为兼容基线；不支持时会提示升级。无需安装配套思源插件。本机地址支持 HTTP，其他服务地址要求 HTTPS，不支持带路径前缀的代理地址。

启用后新增或修改的每条摘录、批注和文章笔记会写入所选笔记本的「划线笔记」父文档下，每条卡片一个文档。再次修改会在原文档追加带时间的更新版本，思源中的补写与旧版本保留；思源编辑不会回传浏览器。图片保存说明和原图链接，图片文件、全文和阅读日志不上传。AI 标签仍需连接 Obsidian 的候选标签文件，不读取思源标签库。

思源关闭或网络中断时，笔记先保存在浏览器队列，恢复后重试，也可以点击「立即同步笔记」。创建和追加使用持久化 ID，响应丢失后先核对已写入版本。若思源文档被删除或移出目标笔记本，会暂停写入；点击设置中的「重新创建缺失文档」后可创建新的副本。删除浏览器笔记只取消待发送内容，不删除已写入思源的内容。

切换输出目标会暂停原队列，切回后继续；更换地址或笔记本不会把旧队列改投新位置。已有笔记和导入备份不会批量补发。Token 仅保存在扩展本机数据库，不返回网页或进入资料备份。卸载扩展会丢失发送记录，跨设备或重新安装后的重复发送不在去重保证内。

## 本地文件

```text
Reading/
  卡片盒.md
  阅读索引.md（旧入口，继续兼容）
  Cards/<article_id>/<摘录标题>--<card_id>.md
  Articles/<article_id>.md
  Daily/YYYY-MM-DD.md
  Data/articles/<article_id>.json
  Data/history/YYYY-MM-DD.jsonl
  Conflicts/<版本摘要>.md（出现双边修改冲突时保留两个版本）
```

每条划线生成一张独立卡片，文章笔记也单独成卡。卡片包含摘录、批注、本地全文链接及同篇卡片链接。划线卡片的可展开上下文只补充前后各一句（划线位于句中时取相邻的句内片段），新增文字合计最多 150 字，超长时以省略号截断，摘录本身完整保留；文章级笔记不附带上下文。Markdown 入口使用 Obsidian 原生嵌入展开卡片；安装配套插件后获得卡片流交互。正文保存为带段落、标题、列表和代码块的 Markdown；目前不下载图片、附件或音视频。

Markdown 元数据版本为 2，包含稳定 ID、来源和时间。JSON/JSONL 仍兼容格式版本 1，新增可选的 bodyMarkdown、bodyCapturedAt 字段。每日记录按本机日期生成，时间戳为 ISO 8601 UTC。升级后自动为旧资料生成卡片；旧记录若缺少正文，需重新打开网页阅读以补存。

在 Obsidian 划线卡片上直接点击引用的摘录，会在侧栏打开本地全文，滚动到对应摘录并高亮；也可通过 Tab 聚焦摘录后按 Enter 或空格打开。卡片视图不再显示独立的定位按钮或上下文展开入口。定位支持跨格式文本和空白差异；重复文字会结合保存的前后文区分。若正文缺失、已变化或仍无法唯一匹配，会提示无法定位，不跳到任意一处相同文字。

浏览器使用 IndexedDB 保存资料，同时读取已连接仓库中卡片“我的批注”的修改。以稳定 ID 和上次成功同步的版本做三方比较：只改一边时同步更新；两边改为相同内容时直接确认；两边改为不同内容时暂停该文章输出，保留原文件和浏览器版本，并在 `Conflicts/` 保存双方内容与原始版本。请合并后将相同的最终笔记分别保存到浏览器和 Obsidian 的“我的批注”，再点击“立即同步笔记”。冲突副本不会自动删除。

同步在浏览器运行且文件夹读写授权有效时执行：启动、打开网页或侧栏、保存笔记时检查，后台通常每分钟检查一次，也可在设置中点击“立即同步笔记”。回读后会刷新已打开的网页笔记；未保存的草稿保留，保存时若已出现新版本会提示合并。浏览器关闭时，Obsidian 修改先留在本地，下次浏览器运行再同步。权限失效后点击“重新授权”。以设置中的同步状态为准。

在 Obsidian 卡片视图中双击正文或空白处，即可原位编辑，也可以从更多操作菜单进入。网页卡片保存后与浏览器双向同步，支持 Markdown、`#标签`、`[[关联笔记]]`，也可以清空。直接编辑 Markdown 时，请修改 `<!-- noting:note:start -->` 与 `<!-- noting:note:end -->` 之间“我的批注”标题下的内容并保留标记。摘录、来源、上下文与元数据由浏览器维护。

旧网页卡片中的“延伸思考”会和原批注显示在同一个输入框中。在卡片视图保存后，两部分合并到同步正文。独立随手记保存在 Obsidian 仓库。插件保存时会检查是否有并发修改，出现冲突时会保留草稿并提示重试。关闭插件视图前请保存草稿。

升级后首次同步会建立每张卡片的基准版本。旧卡片若在升级前已手改生成部分，因缺少可比较的旧内容，会保留文件并提示外部修改；请先备份，将修改复制到浏览器笔记，或恢复原始生成内容后同步。空批注卡也会获得可编辑区域。

在 Obsidian 卡片的「更多操作」中选择「删除笔记」后，下次同步会移除浏览器中对应的划线或文章笔记。同一篇文章的其他卡片和阅读记录仍可查看。浏览器关闭时，删除操作会等到下次连接该笔记库时同步。直接在文件列表移动、重命名或移走 Markdown 文件，沿用原有的文件管理行为。

Agent 可以直接读取 Markdown 和 JSON/JSONL，并创建独立知识笔记。网页摘录及正文应作为引用材料处理。文件中的稳定 ID 用于关联文章、划线与阅读会话。

## 阅读记录与网站权限

识别为文章的网页在前台活跃约 15 秒后收录。计时要求页面可见、窗口聚焦且最近 60 秒有交互。阅读时长为估算值，意外关闭可能损失最后约 10 秒。页面切换时会创建新的会话，最多保留进度和累计活跃时间。首次划线、保存文章笔记或收录阅读会话时尝试提取正文。

扩展需要 HTTP/HTTPS 网站访问权限，以在原网页绘制高亮、提取正文和记录阅读。设置中可以暂停自动阅读记录、排除指定域名及其子域名。无痕模式停用。处理全部在本机进行，扩展没有远端上传或分析服务。

支持普通 HTML 页面。Chrome 内置页面、商店等受限制页面、内置 PDF 查看器以及 iframe 内的内容不在首版范围。网页正文大幅修改、重复且无法唯一匹配的句子会显示「原文位置待重新定位」，已保存的摘录继续保留。页面的 Shadow DOM 内部文字尚不支持选区恢复。

## 备份与恢复

在设置中下载浏览器资料 JSON 备份；Obsidian 中补写的“延伸思考”需要随整个仓库一起备份。导入时完整校验后按稳定 ID 合并，较新版本优先，重复导入会去重。卸载扩展会清除浏览器内的数据，已写入的文件和下载的备份仍可用于恢复。

也可以连接已有的仓库，然后点击「从已连接文件夹恢复」，读取 `Data/` 中的开放格式文件。重新连接已有文件夹时可能先提示生成文件冲突，恢复后重试写入。只有已成功写入的文章与会话能够从文件夹恢复。

在浏览器中删除单条划线或图片笔记后，下次同步会删除 Obsidian 中对应的卡片，包括卡片里补写的内容。侧栏的「移除本页记录」会删除该页全部划线、笔记和会话，移除生成的文章 Markdown 和卡片，更新阅读日志，并记录整页删除状态，避免较旧备份恢复该页记录。

## 开发与验证

```sh
npm run check
npm test
npm run build
npx playwright install chromium
npm run test:e2e
npm run test:obsidian
```

本机开发时，可将项目的 `dist` 设为指向 Chrome 已加载的扩展目录的符号链接，让构建和安装共用同一份文件。设置前先备份原构建目录，保留 Chrome 中已有扩展条目及其安装路径。`npm run build` 会显示实际输出目录；构建后仍需在 `chrome://extensions` 重新加载扩展，再刷新使用中的网页。不要删除并重建这个符号链接，否则构建可能重新输出到独立目录。

浏览器测试使用独立临时配置目录，并可通过 `CHROMIUM_EXECUTABLE` 指定 Chrome for Testing / Chromium。测试使用真实扩展和浏览器文件系统句柄（OPFS）验证写入、冲突与重试。系统原生目录选择弹窗和 Obsidian 外部协议跳转需手动验收。

`npm run test:flomo` 在独立 Chromium 配置中验证设置、真实侧栏保存、去重、错误重试及切换回本地输出；请求由测试替身接收，不访问真实 flomo 账号。

`test:obsidian` 使用浏览器中的 Obsidian API 适配层和本地模拟模型服务，验证自动标签的保存触发、重启恢复、去重、筛选、并发保存、失败重试和关闭行为，以及原文定位与窄屏布局，并输出截图。它不代替真实 Obsidian 或真实模型服务验收。

`node scripts/prepare-preview.mjs` 将最近一次浏览器测试的真实输出和插件构建复制到 `test-results/NotingPreviewVault/`。用 Obsidian 打开该文件夹即可独立验收，不会安装到个人仓库。测试仓库中的随手记和补写是演示内容。配套插件已在桌面 Obsidian 1.14.5 验证；移动端布局与真实设备尚未验收。

架构包括 Content Script（选区、高亮、阅读采集）、Service Worker（事务、消息、文件队列）和设置页（文件夹授权、备份恢复）。内容 UI 使用 Shadow DOM 隔离，网页高亮使用 CSS Custom Highlight API。构建使用 TypeScript 和 esbuild，正文识别使用 Mozilla Readability，Markdown 转换使用 Turndown，IndexedDB 使用 idb。

## 思源插件安装与使用

需要桌面版思源 **3.8.10+**。从 **0.5.0** 起提供正式发布包，尚未上架思源集市。实际验收环境为 macOS ARM64、思源 3.8.10。

1. **下载安装包。** 下载 [思源插件 ZIP](https://github.com/rockbotcc/underline-notes/releases/latest/download/underline-notes-siyuan.zip) 并解压，得到 `underline-notes` 文件夹。使用发布包无需 Node.js 或源码构建；请勿将 GitHub 自动生成的 Source code 当作插件包。发布页同时提供 `SHA256SUMS.txt` 供校验。
2. **找到思源工作空间。** 使用思源当前工作空间的根目录（包含 `conf/`、`data/`），将解压得到的整个 `underline-notes/` 文件夹复制到其中的 `data/plugins/`。最终应直接存在：

   ```text
   <思源工作空间>/data/plugins/underline-notes/plugin.json
   <思源工作空间>/data/plugins/underline-notes/index.js
   <思源工作空间>/data/plugins/underline-notes/index.css
   ```

   这里是插件目录，不是笔记本目录；不要把 Obsidian Markdown 文件直接复制进思源的数据目录。

3. **启用插件。** 打开「设置 → 集市 → 已下载 → 插件」，启用「划线笔记」。首次使用插件时按思源提示确认信任；若列表未出现插件，核对上述层级后重启思源。
4. **打开卡片盒。** 点击顶部「划线笔记 · 卡片盒」图标，或通过命令面板打开。插件本身无需 API Token，也不依赖 Chrome，可直接使用随手记。
5. **可选：连接网页采集。** 下载同一 Release 的 [Chrome 扩展 ZIP](https://github.com/rockbotcc/underline-notes/releases/latest/download/underline-notes-chrome.zip)，按上方手动安装步骤加载，在扩展设置中选择思源，填写地址、Token 和目标笔记本，按[写入思源笔记](#写入思源笔记)验证。采集时需保持思源运行。

**日常操作**

- **随手记**：在「全部笔记」顶部写想法，选择已打开的笔记本，点击「记录」或按 ⌘/Ctrl + Enter。每条记录是该笔记本下独立的原生文档；下次记住所选笔记本，`#标签`、`#领域/写作` 可参与筛选。
- **每日回顾**：点击左侧「每日回顾」，从当前搜索、标签及笔记本范围中每天稳定选取最多 8 张卡。支持上一张、下一张、补写想法和完成回顾；与 Obsidian 共用选卡逻辑，不保存完成进度，不含提醒或间隔记忆算法。
- **补写与打开**：点击卡片「… → 补写想法」或双击卡片，⌘/Ctrl + Enter 保存；Esc 收起并保留草稿。「… → 打开」进入完整原生文档，浏览器后续同步保留补写内容。
- **失败恢复**：草稿和目标笔记本保存在工作空间的插件数据中。写入结果不确定时保留草稿，点击「重试记录」或「重试保存」核对，避免重复创建。首版面向单个活跃客户端，不支持多设备同时编辑同一份插件草稿。

**升级**：先停用插件，将旧插件文件夹备份到 `data/plugins/` 之外，再复制新发布包中的文件并启用，关闭旧卡片盒页签后重新打开。保留 `data/storage/petal/underline-notes/` 中的草稿与保存状态。卸载插件不会删除原生卡片和已保存想法。

开发者也可使用 Node.js 22.18+，运行 `npm ci`、`npm run build`，安装 `dist-siyuan/underline-notes/`。运行 `node scripts/package-release.mjs` 可生成 `dist-release/underline-notes-siyuan.zip`。

思源版暂不提供按来源聚合、阅读足迹、AI 自动标签、移动端卡片盒或双向修改浏览器摘录；普通文档不会自动加入卡片盒。详见[插件说明](siyuan/README.md)、[安装指南](INSTALL.md)、[方案](docs/siyuan-plugin-plan.md)和[测试记录](docs/siyuan-testing.md)。
