# 思源笔记接入方案

日期：2026 年 11 月 12 日。项目基线：Underline Notes 0.4.1，提交 `aba253c`。

建议新增「思源笔记」输出目标，由 Chrome 扩展后台直接调用思源内核 HTTP API。第一版按卡片单向写入，每条划线或文章笔记对应一个思源文档；浏览器修改已发送内容时，在该文档内追加一个版本，保留用户在思源中的编辑。单纯写入无需安装思源插件。2026-11-13 根据用户进一步要求，增加配套的原生卡片盒插件，优先实现卡片流、搜索筛选和补写想法，见 [插件方案](siyuan-plugin-plan.md)。

本方案依据现有项目代码与思源官方文档、源码制定。接口基线为当前发布版 v3.8.10；第一版已完成实现，并在独立的思源 3.8.10 macOS ARM64 内核通过真实写入测试；旧版本尚未承诺兼容。详见 [测试记录](siyuan-testing.md)。

## 接入路径与依据

思源提供本地 HTTP API，默认端点为 `http://127.0.0.1:6806`，使用 `Authorization: Token …` 鉴权。当前文档把 API Token 入口列在「设置 → 认证」；官方剪藏扩展说明仍写「设置 → 关于」，安装指南应兼顾版本差异。[API 规范](https://github.com/siyuan-note/siyuan/blob/v3.8.10/docs/API.md#specification)、[官方剪藏扩展](https://github.com/siyuan-note/siyuan-chrome#-usage)

思源普通笔记本中的 `.sy` 文档为 JSON，不能把现有 Obsidian 的 Markdown 目录直接当成思源工作空间写入。[官方存储说明](https://github.com/siyuan-note/siyuan/blob/v3.8.10/README.md#how-does-siyuan-store-data)

| 路径 | 用户配置 | 项目代价 | 判断 |
| --- | --- | --- | --- |
| 扩展直接调用思源内核 API | 地址、Token、目标笔记本 | 增加输出适配器与持久队列 | 推荐，最贴合已有 flomo 输出结构 |
| 开发配套思源插件 | 还需安装、启用插件 | 维护第三个应用端及通信协议 | 已新增配套卡片盒；采集仍复用扩展 API 输出 |
| 导出 Markdown 后手动导入 | 反复导出、导入 | 较低 | 可作迁移方式，不能满足持续自动写入 |

请求放在扩展 service worker。Chrome 官方允许具备 host permissions 的扩展后台执行跨域请求；当前项目已经声明 HTTP 与 HTTPS 主机权限。内容脚本只提交笔记保存意图，不提供任意 API 路径或读取 Token。[Chrome 网络请求说明](https://developer.chrome.com/docs/extensions/develop/concepts/network-requests)

本地模式要求思源内核运行；关闭思源时先保存浏览器队列。可配置其他端点，但第一版优先验收同机桌面模式。自部署 HTTPS 服务作为第二批支持；移动端查看依赖用户自己的思源同步配置，本功能不同步浏览器划线定位和阅读日志。

## 用户流程

1. 打开扩展设置，在「笔记写入位置」中选择「思源笔记」。延续当前单一输出目标设计。
2. 地址预填 `http://127.0.0.1:6806`，填写 API Token。
3. 点击「测试连接」，读取版本和可用笔记本；这个动作不创建笔记。
4. 选择已打开、可写的笔记本，默认建立一个「划线笔记」父文档。第一版不提供任意复杂路径模板。
5. 保存配置后，新建一条网页摘录，侧栏显示「已保存在浏览器 → 等待写入思源 → 已写入思源」。连接失败时显示可操作的原因。

父文档在首次实际写入时创建并记录 ID。不要仅靠标题复用同名文档；已有多个同名目标时要求明确选择。后续所有写入使用 ID 定位，用户重命名父文档不应使绑定失效。

默认只写入启用后新增或修改的卡片。切换输出位置暂停原目标队列，切回后继续；不把本地全部历史记录或导入备份自动发送到思源。第一版不做批量历史迁移。

## 内容组织与同步规则

建议采用以下文档树。一个网页可以产生多个卡片文档，与项目现有卡片粒度一致。

```text
用户选定的笔记本
└── 划线笔记
    ├── 摘录的简短标题
    ├── 另一条摘录的简短标题
    └── 文章笔记的简短标题
```

每个文档包括批注、引用摘录或图片说明、来源文章标题与链接、摘录时间。初次内容写入一个可识别的版本块，正文其他位置供用户自由补充。显示标题允许重复，身份使用独立 ID。

| 行为 | 第一版约定 |
| --- | --- |
| 新增文字划线、批注、文章笔记 | 创建独立文档 |
| 保存完全相同的内容 | 不重复发送 |
| 修改尚未发送的笔记 | 合并为最新待发送内容 |
| 修改已发送的笔记 | 原文档追加带时间的「更新」块，保留旧版本 |
| 在思源编辑或补写 | 原样保留，不回传浏览器 |
| 删除浏览器记录或清空文章笔记 | 取消尚未发送的任务；已写入思源的内容保留 |
| 用户在思源删除目标文档 | 暂停该卡片输出，提供重新创建操作，不自动复活 |
| 思源未运行、网络中断 | 本地保留，恢复后重试 |
| 重命名或移动文档 | 同一绑定范围内按 ID 继续；跨笔记本移动先暂停并核对目标 |

第一版选择追加版本，是因为用户可以在思源中自由修改内容。直接调用块更新接口并不能自然获得双向合并能力。未来若需要原位更新，应设计明确的受管理块、远端修改检测和冲突处理；「先读后写」本身也不能消除两次请求之间的并发编辑窗口。

图片先保存现有说明和原图链接，并明确提示未上传图片文件；避免把图片数据静默丢弃。附件上传作为紧接着的增强项。全文、上下文展开、阅读日志、思源内专属卡片流暂不进入第一版。

手写标签第一版保留原文，不承诺已经转换为思源原生标签。现有 AI 自动标签只读取 Obsidian 导出的候选列表，不能自动宣称兼容思源标签库；未连接该候选来源时，应明确显示不可用。思源原生标签格式适配与候选读取另行增加。

## API 与版本选择

v3.8.10 是本次查询到的正式发布版。第一版以此为验收基线，不把当前文档中的新能力直接承诺给所有旧版。[发布记录](https://github.com/siyuan-note/siyuan/releases/tag/v3.8.10)

| 用途 | 接口 |
| --- | --- |
| 检测版本 | `/api/system/version` |
| 选择笔记本 | `/api/notebook/lsNotebooks` |
| 检查文档能力 | `/api/notebook/getNotebookConf` |
| 按父文档创建卡片 | `/api/filetree/createDocByParent` |
| 追加修改版本 | `/api/block/appendBlock` |
| 按已分配 ID 核对内容 | `/api/block/getBlockKramdown` |
| 确认文档所在笔记本 | `/api/filetree/getPathByID` |
| 补充来源属性 | `/api/attr/setBlockAttrs` |
| 后续上传图片 | `/api/asset/upload` |

上述接口及参数见[官方 API 文档](https://github.com/siyuan-note/siyuan/blob/v3.8.10/docs/API.md)。新建文档接口允许客户端预先分配 ID，已有 ID 会返回冲突；块写入允许显式指定合法块 ID。这些能力为失败核对提供基础，但仍需客户端实现恢复流程。

不以「相同标题或路径」作为防重依据，也不把 HTTP 200 直接当成功。需要校验业务 `code`、返回数据类型和目标 ID。旧式 `createDocWithMd` 不应被当成 upsert 接口。

连接时读取版本与能力声明；缺少所需能力时提示升级。若确有旧版本用户需求，应针对其版本验证兼容分支，不能在新接口写入失败后立刻降级到旧接口再写一次。

## 队列与恢复设计

复用项目「先入 IndexedDB，再后台输出」的路径，新增专用 `siyuanJobs` 和 `siyuanBindings` 存储。文章数据与任务在同一个本地事务提交；网络请求在事务外执行。

建议记录以下字段：

```ts
type SiyuanSettings = {
  baseUrl: string;
  apiToken: string;
  profileId: string;
  notebookId: string;
  parentDocId?: string;
};

type SiyuanBinding = {
  profileId: string;
  articleId: string;
  cardId: string; // annotation.id 或 page
  docId: string;
  lastSentHash?: string;
};

type SiyuanJob = {
  profileId: string;
  articleId: string;
  cardId: string;
  revision: string;
  docId: string;
  versionBlockId: string;
  contentHash: string;
  payload: string;
  state: 'pending' | 'sending' | 'uncertain' | 'sent' | 'blocked';
  attempts: number;
  retryAt?: number;
  errorCode?: string;
};
```

`profileId` 绑定一组输出目的地。变更地址、笔记本或父文档时，旧任务保持原绑定并暂停，不能把它们改投新位置。Token 轮换不必创建新绑定，但需重新验证目标；同一端口启动了其他工作空间时，笔记本和父文档校验应阻止误投。

首次创建前，先把文档 ID、版本块 ID 和不可变发送快照持久化。ID 按思源要求生成，不能直接使用本项目 `a_…`、`h_…` 格式。请求发送后按以下规则处理：

1. 收到成功响应后核对目标，记录绑定与已发送内容摘要。
2. 超时、连接断开或 service worker 重启后，将未完成请求视为结果不确定，先按原 ID 读取远端。
3. 找到预期文档或版本块时核对身份、所属笔记本和内容，再补记成功；不分配新 ID 重发。属性补写失败也只重试属性步骤。
4. 只有确认不存在且目标可用，才以原 ID、原快照重试。鉴权失败、索引未就绪或读取失败不能等同于不存在。
5. 发现内容不同或归属不符时暂停，展示「需核对」，不覆盖或删除远端记录。

追加版本同样先持久化新版本块 ID。每次追加一个带固定 ID 的容器块，内部包含该版本的批注、摘录与来源；其 Markdown 表达、ID 保留和返回后的读取行为是联调验收项。如果指定 ID 的容器方案不可用，首版应退回「每个版本独立文档」并明确展示，不使用无法核对的盲目追加。

去重以当前待发内容和最近已发送内容比较，不按全文历史摘要永久去重：用户经历 A → B → A 时，最后一次 A 仍是一项有效修改。发送中的快照保持不变，新编辑保留为下一任务；旧请求成功不能清除更新的任务。

使用现有输出锁串行发送，每批限量，失败退避并加抖动。网络失败和暂时不可用可重试；Token 无效、笔记本关闭或锁定、目标缺失、版本不支持应暂停并提示处理。手动「立即同步」可提前触发可重试任务，但不跳过结果核对。

这些保证限定在同一扩展实例及其持久数据库内。重新安装扩展、丢失绑定或多设备同时发送同一份备份，不能据此承诺全局去重。第一版不开放跨设备补发流程。

## 对现有代码的改动

| 文件 | 建议改动 |
| --- | --- |
| `shared/model.ts` | `outputTarget` 增加 `siyuan`，增加连接设置，保留现有默认值 |
| `browser/src/siyuan-api.ts` | 新增 URL 校验、鉴权请求、响应校验、创建与核对、错误分类 |
| `browser/src/siyuan-content.ts` | 新增思源内容转换与来源属性；不直接复用带 Obsidian 嵌入和文件链接的 Markdown |
| `browser/src/siyuan-output.ts` | 新增任务状态机、绑定管理、重试与恢复 |
| `browser/src/db.ts` | 数据库 v2 升级到 v3，增加两个存储和索引 |
| `browser/src/output.ts` | 显式分派三个输出目标，保持现有锁及调度入口 |
| `browser/src/background.ts` | 保存时入队、连接测试 RPC、配置校验、状态与删除语义、内容脚本返回字段白名单 |
| `browser/src/options.ts`、`browser/options.html` | 连接配置、测试、笔记本选择、状态与错误处理 |
| `browser/src/content.ts` | 思源状态、设置入口、删除提示与回顾入口 |
| `README.md`、`INSTALL.md`、`PRIVACY.md` | 安装步骤、版本条件、内容范围、保留版本与数据流向 |
| `tests/`、CI | API 与队列测试、模拟内核浏览器测试、真实实例验收记录 |

有三个现有实现细节必须一起处理：

- `db.ts` 的升级函数目前无条件创建 `flomo` store。升级到 v3 时应按 `oldVersion < 2`、`oldVersion < 3` 分段，否则老用户升级可能因重复建 store 失败。
- `background.ts` 的 `GET_PAGE` 当前展开整个 settings 后清除 flomo URL 和 AI 配置。新增 Token 后应改为明确的公开设置白名单，防止凭据随新字段泄露给内容脚本。
- `output.ts` 当前把非 Obsidian 输出直接当成 flomo；设置页与内容脚本也有大量二选一分支，需要完整改为三种目标，不仅增加下拉选项。

首版提取最小的输出分派和公共状态结构即可，暂不把 Obsidian 文件同步和 flomo 队列全部重构为通用框架。

## 凭据与内容边界

Token 仅存扩展本机数据库，不进入 JSON 备份、网页消息和日志。当前备份只包含文章与阅读会话，应保持这个边界。请求仅允许固定 API 路径，使用 `credentials: 'omit'`，禁止自动跳转，超时后进入核对状态。

首版允许本机回环地址使用 HTTP，其他服务地址要求 HTTPS。拒绝 URL 内嵌账号密码、查询串和片段。目标地址只由扩展设置页配置；内容脚本不能借此调用任意思源接口。

写入范围是用户保存的摘录、批注、来源和时间；全文、阅读轨迹及其他思源笔记不随之发送。启用 AI 标签时仍使用现有独立模型配置和发送范围。

## 验收与实施节奏

第一步先用隔离的测试工作空间验证真实内核，记录版本、系统和请求结果，不连接用户日常笔记本。

| 阶段 | 产出 | 粗估投入 |
| --- | --- | --- |
| 接口验证 | 创建、读取、固定 ID 追加、错误恢复、Markdown 与中文内容显示 | 1 人日 |
| 核心输出 | 数据迁移、持久队列、目的地绑定、创建及追加恢复 | 2 至 3 人日 |
| 用户界面 | 设置、测试连接、笔记本选择、侧栏状态和错误处理 | 1 至 2 人日 |
| 验证与文档 | 浏览器测试、真实思源验收、现有功能回归、安装说明 | 1 至 2 人日 |

合计约 5 至 8 人日，属于熟悉当前代码的单人开发估算；不包含旧版兼容、图片附件、原位更新或双向同步。若接口验证发现固定 ID 或恢复行为不满足要求，应先调整写入策略再实施界面。

发布前至少覆盖：

- 文字划线、只有摘录无批注、文章笔记、中文、多行 Markdown、超长内容、来源标题含斜杠。
- 重复保存不重复发送；连续离线修改仅发送最新待发版本；已发送后的修改追加版本并保留思源补写。
- 请求已成功但响应丢失、worker 在请求中被回收、属性补写中断，恢复后不重复创建。
- 新编辑发生在旧请求发送中，最新任务不被旧成功响应清除。
- 思源关闭后恢复、Token 错误、笔记本关闭或锁定、目标移动或删除、同端口切换工作空间。
- 切换目标暂停正确的队列；修改目的地不转发旧任务；删除操作遇到发送中请求时明确提示已写入内容保留。
- v1 与 v2 数据库均可升级，原有 Obsidian 文件同步、flomo 和备份功能不回归；网页消息与备份中不存在 Token。

开发时运行现有 `npm run check`、`npm test` 和相关浏览器用例，并新增思源模拟服务用例。真实思源实例验收必须单列，模拟服务通过不能代替内核兼容验证。第一版的执行结果见 [测试记录](siyuan-testing.md)。

后续增强按「图片附件 → 思源原生标签 → 历史迁移 → 原位更新和冲突处理 → 双向编辑」推进。只有需要思源内专属交互或可靠的编辑协同时，再评估配套插件。
